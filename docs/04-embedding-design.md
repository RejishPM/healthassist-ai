# Embedding Design

## Objective

The embedding layer converts text into vectors that can be compared semantically.

## Provider Abstraction

HealthAssist does not directly couple the application to one embedding provider.

Conceptually:

Embedder
   |
   +-- OllamaEmbedder
   |
   +-- BedrockEmbedder

## Ollama

Used primarily for development.

Benefits:

- No API cost for local inference
- Useful for experimentation
- Avoids unnecessary cloud calls during development

Current embedding model:

nomic-embed-text

Current embedding dimension:

768

## Bedrock

Planned for cloud/demo/production scenarios.

The embedding abstraction allows the implementation to switch providers without rewriting the ingestion or retrieval workflow.

## Persistence

Embeddings are stored separately from document chunks.

This allows the same document chunk to potentially have embeddings generated by multiple:

- providers
- models

The uniqueness rule is conceptually:

document_chunk_id + provider + model

This prevents accidental duplicate embeddings for the same model.
